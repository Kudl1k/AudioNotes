# Releasing Soniquill

Direct distribution target: signed and notarized Apple Silicon macOS 15+ app inside a DMG. Final production bundle ID is `cz.kudladev.soniquill` on macOS and iOS/iPadOS. Apple Developer/signing setup, physical iPhone installation and App Store Connect/TestFlight distribution of 1.0.0 build 1 are established; preserve the working signing configuration. This macOS DMG procedure is separate from that confirmed iOS distribution. Legacy storage and credential lookup identifiers remain separate from product identity; see [SONIQUILL_RENAME.md](SONIQUILL_RENAME.md). Version is `Configuration/Version.xcconfig`; increase `CURRENT_PROJECT_VERSION` on every shipped build. Release tags are `v<MARKETING_VERSION>` and titles are `Soniquill <MARKETING_VERSION>`. Do not reuse a version or tag. The repository origin is the source of the GitHub owner/repository; do not copy guessed hosting URLs into release files.

## Identity, installation and storage

Bundle identity: `cz.kudladev.soniquill`; owner copyright: `© 2026 Štěpán Kudláček`; deployment target macOS 15.0; architecture `arm64` only. Universal and Intel releases are not supported. Native local Whisper is enabled only on Apple Silicon. The app keeps Hardened Runtime, has no JIT/unsigned-memory exceptions, and uses an empty production entitlements dictionary. Direct distribution remains non-sandboxed; changing this requires retesting the full product. Network access is outbound and provider-specific; no microphone permission is requested. The App Transport Security exception for development host `mac.lab` has been removed.

Application Support contains `default.store` (SwiftData metadata) and `AudioNotes/Recordings`, `AudioNotes/Sources/<UUID>`, `AudioNotes/Models/Whisper`, and `AudioNotes/Deletion-<UUID>` transaction journals. Retrieval indexes are in-memory and rebuildable. A pre-v1 `AudioNotes/Backups/pre-v1.store` is one local structured-metadata snapshot only. It excludes original recordings/sources/models, preferences and Keychain credentials. Copy the complete database together with its WAL/SHM siblings and the whole legacy `AudioNotes` directory after quitting the app to make a full manual backup. macOS system backup is the way to retain preferences and credentials. Keychain services retain the existing stable service IDs `cz.kudladev.AudioNotes.provider-credentials` and `cz.kudladev.AudioNotes.chatgpt-credentials` across the new permanent bundle ID.

The v1 schema identifier is `1.0.0`. Its persistent model declarations are registered by `LibrarySchemaV1`. The checked-in on-disk fixture at `AudioNotesTests/Fixtures/v1/library.sqlite` is generated from synthetic data by the opt-in `AUDIONOTES_WRITE_V1_FIXTURE=1` test; normal test runs only read it and prove preservation of relationship history, source data, chat and cost. Before changing models for v2, preserve every v1 model declaration in an immutable nested schema, add an explicit migration stage, and test the archived fixture against it. Never change v1 models in place or delete/replace a store after an open error. Backups are created before opening an existing store, and failed opens retain it with Retry, reveal and diagnostic actions.

## GitHub hosting

GitHub Releases are canonical versioned downloads. For release `1.0.0`, use `AudioNotes-1.0.0.dmg`, tag `v1.0.0`, title `Soniquill 1.0.0`; the download URL is `https://github.com/Kudl1k/AudioNotes/releases/download/v1.0.0/AudioNotes-1.0.0.dmg`. GitHub Pages is the single stable Sparkle feed. `.github/workflows/publish-appcast.yml` deploys only an `appcast.xml` asset attached to the latest published stable release. It verifies the feed against the configured Ed25519 public key, downloads every full DMG from the exact versioned GitHub Release URL, checks length/signature/HTTPS, rejects an empty feed, then deploys via the official GitHub Pages artifact/actions flow (including the hidden `.nojekyll` marker) and verifies the public bytes and enclosure URLs. It cannot publish a fabricated appcast. The workflow is dispatch-only and runs only on `main`: the `github-pages` environment's deployment policy allows the `main` branch, and a `release` event would run on the tag ref and be rejected. `release.sh --publish` dispatches it with `--ref main` after publishing; manual dispatch (Actions → Publish Sparkle appcast → Run workflow on `main`, tag input) may retry deployment only for the current latest stable tag.

One-time repository configuration: in GitHub Settings → Pages, set Build and deployment → Source to **GitHub Actions**. No permanent `gh-pages` branch is required. Audit 2026-10-01: the public repository reports `has_pages=true` with a `github-pages` environment limited to `main` and no deployments yet, consistent with the GitHub Actions source (the authenticated Pages API was not available to confirm it); the feed returns 404 and there is no release asset. Repository variable `SPARKLE_PUBLIC_ED_KEY` must be added once the Sparkle key exists. Therefore these cannot yet be verified: Pages URL, GitHub Release artifact URL, production feed read by Sparkle. Enable Pages first, then publish the first genuinely signed, notarized, accepted DMG/appcast release and verify `https://kudl1k.github.io/AudioNotes/appcast.xml` and its enclosure. Do not set the feed/public key in the app until that succeeds. A signed update test from an installed previous version is still mandatory; publishing infrastructure alone is not update acceptance.

## Build, sign, notarize and package

1. Bump `MARKETING_VERSION` and monotonically increment `CURRENT_PROJECT_VERSION`; add user-facing notes in `docs/release/<version>.md`.
2. Run `scripts/release/release.sh --dry-run` for a local unsigned packaging rehearsal. Its output DMG is explicitly prefixed `UNSIGNED-DO-NOT-DISTRIBUTE`.
3. Configure the existing Developer ID, notary profile and Sparkle key names/public key in the environment. Keep values out of shell history; no passwords or private key files are required. Run `scripts/release/release.sh --package`. It runs all Debug tests and release-tool tests, archives the optimized Release app, verifies team/code signature/hardened runtime/identity/version/arm64/icon, builds a drag-to-Applications DMG, submits app and DMG to Apple, waits for `Accepted`, staples/verifies Gatekeeper tickets, signs the DMG with Sparkle, generates appcast and checksum. Production feed URLs derive from the Git remote.
4. Install this exact candidate on a clean account, preserve real test data and local models, quarantine-check it, run Help/onboarding/core workflows and install a signed test update. Record manual checks against that exact version, build, source commit and DMG SHA-256 in a local JSON file using `docs/release/acceptance.example.json`. No template record counts as completed acceptance.
5. Run `scripts/release/release.sh --publish` on a clean checkout at that exact source commit. It verifies the acceptance JSON, same DMG checksum, notarization, signature, Gatekeeper and every appcast enclosure. It creates the GitHub Release as a draft, attaches DMG/checksum/appcast, then publishes and dispatches Pages. Verify the public appcast/asset and Sparkle update on a previously installed release before announcing.
6. Keep the archive, dSYMs, checksums, release notes and signed appcast privately for recovery. For rollback, stop automatic updates by publishing a higher build with a fix; never replace a stable tag/appcast with older build numbers. Retain prior signed releases; investigate failed notarization/signatures and do not publish through them.

The local publisher requires `gh` and an authenticated account with access to Kudl1k/AudioNotes. Publishing is a consequential remote operation and is isolated to the explicit `--publish` mode, guarded by exact-artifact manual acceptance. The GitHub Pages workflow is also available for retries. See [release checklist](RELEASE_CHECKLIST.md) for one-time and each-build acceptance.
